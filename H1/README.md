## 二、接线表

| 模块 | 引脚 | ESP32 | 说明 |
|---|---|:--:|---|
| **HC-SR04** | VCC | **3.3V** | ⚠️ 千万别接 5V，Echo 会输出 5V 烧引脚 |
| | GND | GND | |
| | Trig | GPIO 25 | 输出触发脉冲 |
| | Echo | GPIO 18 | 输入，测回波时长 |
| **无源蜂鸣器** | VCC | **3.3V** | 不要接 5V（低电平触发模块在 5V 下可能关不断） |
| | GND | GND | |
| | I/O | GPIO 4 | 控制信号 |

### 接线三条铁律

1. **所有 GND 必须连到一起（共地）**。不共地是最隐蔽的故障：模块有电、灯也亮，但数据全乱。
2. **上电前先用眼睛核对一遍**，特别是 VCC 有没有接错到 5V。
3. **先接线，再插 USB**。不要带电插拔模块。

## 四、第 3 步的验证动作（照着做）

烧进 `03_five_level` 之后，打开串口监视器（波特率 **115200**），然后：

| 动作 | 预期 |
|---|---|
| 手放在 150cm 外 | 显示 `SAFE`，静音 |
| 慢慢靠近到 80cm | 变 `SLOW`，听到「滴……滴……滴」慢速 |
| 靠近到 35cm | 变 `MID`，节奏明显加快 |
| 靠近到 12cm | 变 `FAST`，「滴滴滴滴」很急 |
| 贴到 3cm | 变 `DANGER`，连续长鸣 |
| **快速拿远** | **立刻回到 SAFE，不卡住** |

**最后一条是关键测试。** 你仿真版的双条件滤波在这里会失败（手一拿远就卡在近距离），中值滤波能通过。这就是改进的价值。

## 五、这一版改了什么（也是你面试要讲的内容）

### 改动 1：滤波从「双条件判断」→「三帧中值」

| | 仿真版（双条件） | 真机版（三帧中值） |
|---|---|---|
| 做法 | `if (d > last+80 && last<15) d = last;` | 连测 3 次，排序取中间值 |
| 能滤掉单次毛刺 | ✅ | ✅ |
| 真实远离时不误判 | ❌ **会卡住** | ✅ |
| 需要调阈值 | 需要（80、15 两个数） | **不需要** |
| 代价 | 快（1 次测量） | 慢（3 次约 75ms） |

**面试可以这样讲：**
> 「我第一版用的是双条件判断——距离突然增加 80cm 以上、且上一帧还在 15cm 以内，就判定为盲区假值。这个逻辑在静止场景能用，但做标定实验时发现，当我把障碍物从很近快速拿远，真实的变化也被当成假值压回去了，距离卡死不动。
> 后来我改成三帧中值滤波：连续测三次，排序取中间那个。单次的毛刺会被自动丢掉，而连续三次都变大就是真实变化，会正常保留。好处是不需要调任何阈值，逻辑也更简单。」

**这个"两版迭代"的故事，比你原来"我用了一个滤波"强得多。**

### 改动 2：蜂鸣节奏从 `delay()` → `millis()`

仿真版是 `tone(); delay(600);`——这 600ms 里**完全没有测距**。

按 1.2m/s 的步速算，600ms 能走 **72cm**。也就是说：**响得最急的时候，恰恰是最看不见的时候**。逻辑上是反的。

真机版用 `millis()` 记时间戳，响完立刻返回，主循环继续测距。

**这一条也直接是你后面上 FreeRTOS 的动机**（见 `04-教程-FreeRTOS.md`）。

### 改动 3：增加原始数据打印

每次打印 `距离 + 档位`，为标定实验和排障准备。

## 六、跑通之后立刻做标定实验

跑通 H1 的当天就做，趁热。

### 实验 A：测距精度（60 分钟）

1. 把超声波固定在桌边，朝向空旷处
2. 用卷尺从传感器前端面量起，依次设 `5/10/15/20/25/30/40/50/60/80/100/120/150/180/200 cm`
3. 每个点放好硬纸板 → 等读数稳定 → **记录 20 次**
4. 算每个点的：**平均值、平均绝对误差、最大误差**
5. 记录：**从哪个距离开始读数不稳**（这就是有效量程上限）

产出一张表，然后你就能在简历上写：
> 完成 15 个距离点 × 20 次采样的测距标定，0.2–2.0m 量程内平均误差 ±X cm、最大误差 Y cm

### 实验 B：五档触发点校准（30 分钟）

从 200cm 慢慢推近，记录每一档**实际触发**的距离（用卷尺读，不看屏幕）。

| 档位 | 设定阈值 | 实测首次触发 | 偏差 |
|---|:--:|:--:|:--:|
| SAFE→SLOW | 100 | | |
| SLOW→MID | 50 | | |
| MID→FAST | 20 | | |
| FAST→DANGER | 5 | | |

**面试话术**：阈值不是拍脑袋定的——按人正常步速 1.2m/s 反推，从 100cm 到障碍物约 0.8 秒，所以 100cm 给慢提示、20cm 给快提示；再用卷尺逐点实测校准。

### 实验 C：响应延迟（30 分钟）

手机开慢动作录像（120fps），拍"纸板出现 → 蜂鸣器启动"的过程，逐帧数。

**这个数字会暴露一个问题**：因为三帧中值要 75ms，加上主循环，延迟可能到 100ms 以上。**这就是你引入 FreeRTOS 的量化依据。**

### 实验 D：稳定性（边做别的事边跑）

连续运行 2 小时，记录：误报次数、漏报次数、重启次数。
